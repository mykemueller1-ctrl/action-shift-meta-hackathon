Action Shift · From Craving to Kitchen

The customer changed the order. Did the kitchen get the right version?

Food and labor still cost money when a team makes the wrong version. Action Shift keeps the guest’s request, the restaurant’s decision and the kitchen’s version together.

Myke Mueller · Community Tap & Pizza, Fort Dodge, Iowa · Founder of Never86’d Watch the demo ↓

Fictional restaurant records. Recorded Muse results. Simulated handoffs. The video uses visual captions. No voice is attributed to Myke. Model responses shown are saved results from real Meta API tests using synthetic inputs. Opening this page makes no model request. Kitchen, table and remedy receipts are local simulations. No customer message, real order, booking, payment or refund is created.

The decision stays tied to its source. The browser journey verified a real server restart, a saved correction applied within its restaurant and date, the exact source of an adopted proposal and an unsent reply edit. All 90 focused tests passed. The three fresh model cases retain a failed extraction and a qualified reply. Those results remain available with their limitations.

The operator makes the commitment

The old approval cannot cover the new order.

An expired special stays expired. Conflicting quantities stay open until clarified. The kitchen simulator acknowledges one exact version. When the guest changes it, the earlier receipt stays visible and the new request needs another decision.

The front desk also includes ordinary direct orders, table requests and service recovery. The source records what has been demonstrated and what remains to connect.

Explore the working prototype

Run it locally.

This page hosts the video. The interactive prototype runs on your computer with Node.js 22 or newer. Recorded replay needs no API key or dependency installation.

git clone https://github.com/mykemueller1-ctrl/action-shift-meta-hackathon.git
cd action-shift-meta-hackathon
node src/front-desk-demo.mjs

Then open http://127.0.0.1:4330/front-desk. Stop the local server with Ctrl+C. Case state resets on restart while reviewed restaurant corrections reload from a local file. Missing proposal fields still block adoption.
