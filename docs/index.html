The operator makes the commitment

The old approval cannot cover the new order.

Muse helps read the request. It can still miss a detail. In this walkthrough, a person completes a missing pickup location from the original message and records why. The original model answer stays intact.

Then the operator checks the price, timing and capacity. A later guest change needs a fresh decision. The kitchen simulator acknowledges the new version while the old receipt stays visible.

Explore the working prototype

Run it locally.

This page hosts the video. The interactive prototype runs on your computer with Node.js 22 or newer. Recorded replay needs no API key or dependency installation.

git clone https://github.com/mykemueller1-ctrl/action-shift-meta-hackathon.git
cd action-shift-meta-hackathon
node src/front-desk-demo.mjs

Then open http://127.0.0.1:4330/front-desk. Stop the local server with Ctrl+C. Cases reset on restart. Reviewed restaurant corrections reload from a local file. Unknown allocations still block adoption.

The latest source also offers a separately reviewed 11-pizza request. Choose “Revised crew order · 11 pizzas” to inspect it. This video keeps the earlier human-completion example.

All earlier model failures and the reasoning comparison remain in the source. Human completion repairs the working draft. It does not turn a model failure into a success or train the model.
